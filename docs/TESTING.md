# Testing

## How tests are discovered

- Every `apps/*` and `packages/*` directory with a `wj.toml` is a package. CI runs `wj build` then
  `wj test` inside it (`.github/workflows/ci.yml`, job `build-apps`). `wj test` finds `tests/**/*.wj`
  and `*_test.wj` / `test_*.wj` files; test functions are `fn test_*` / `@test`.
- A package with no test function would pass silently, so `scripts/assert-package-tests.sh` fails CI when a
  package has none (uses `wj test --list` when the compiler supports it, else greps).
- `scripts/check-orphan-tests.sh` (job `orphan-tests`, no builds) fails when a test file sits in a
  directory with no `wj.toml` (the loop skips it) or outside `apps/` and `packages/`
  (roots in `scripts/wj-test-roots.txt`). Exceptions: `scripts/orphan-allowlist.txt` (`path | reason`).

## Adding a test

1. Put `foo_test.wj` (or `tests/foo.wj`) in the package with at least one `fn test_...()`.
2. New package: create `apps/<name>/` or `packages/<name>/` with `wj.toml`; the CI loop picks it up.
3. Run locally: `cd packages/<name> && wj build src && wj test`.

## Compiler pin

The `[toolchain]` table in `wj.toml` holds the full SHA; `ci.yml` `WINDJAMMER_REF` must match (job `pin-check`). The SHA must exist
on the compiler remote or the checkout fails. Bump pin and ref together.

## Unverified

CI has not been run. `wj test` exits 0 on zero tests in the current compiler (a fix is pending there), which
is why the assertion script exists; it stays useful afterward.

## Public hygiene gate

`scripts/public_hygiene.wj` fails when a tracked file name or content matches a forbidden-term pattern from
`scripts/public-hygiene-patterns.txt` (a copy of the compiler repo's list). Run
`wj run --interpret --allow process --allow fs.read --allow env.read --allow console scripts/public_hygiene.wj`,
with `--self-test` to prove the matcher fires on planted terms. CI runs both in job `build-apps`.

## Idiom audit

`scripts/idiom_audit.wj` counts, per package and app, the forms that idiomatic Windjammer does not need (explicit
clones and borrows, width casts, `.unwrap()`, `+` string building, Rust-style types and macros, workaround comments)
and writes the ranked report [IDIOM_AUDIT.md](IDIOM_AUDIT.md). `--write` regenerates it, `--check` fails when it is
stale, `--self-test` plants each pattern. Code that must stay shaped around an open compiler gap carries a
`// wj-gap: <id>` comment; the shrink-only ledger `scripts/idiom-gap-ledger.txt` caps the marked sites per id. CI
runs the self-test and `--check` in job `build-apps`.

## Golden programs

`golden/` holds the idiomatic reference programs: small (30 to 120 lines), one idiom each, a header that says what it
teaches, and an `.expected` file with the exact output. `scripts/golden_gate.wj` enforces the rules: `--check` (static
rules and fresh generated files), `--interp <wj>` and `--compiled <wj>` (each program must print its `.expected`
file in both modes, so the two never drift), `--self-test` (plants a violation of every rule). `golden/INDEX.md` and
`llms-golden.txt` (all programs with their output, sized for in-context use) are generated by `--write`.
`scripts/idiom_audit.wj --golden` fails on any audited pattern or `wj-gap` marker in a golden program. CI runs the
interpreted checks on every push and the compiled comparison in the weekly job.

## Health gate: every package and app, interpreted (and compiled)

The interpreter is a first-class way to run Windjammer, so the whole ecosystem is proven to work in it on every push.
`scripts/health_gate.wj` runs `wj test --interpret` (and, optionally, compiled `wj test`) in every `apps/*` and
`packages/*` directory and decides pass or fail from the results.

```bash
# from the repo root; interpreted sweep of everything (about a minute), exit 0 means the gate holds
wj run --interpret --allow process --allow fs.read --allow fs.write --allow env.read --allow console \
    scripts/health_gate.wj "$(command -v wj)" /tmp/health interp

# interpreted and compiled, with the drift comparison (compiled is slow: minutes per package on a cold build)
SLOT_CMD=/path/to/your/build-slot-wrapper HEALTH_JOBS=2 wj run --interpret ... scripts/health_gate.wj "$WJ" /tmp/health both

# a few directories only
wj run --interpret ... scripts/health_gate.wj "$WJ" /tmp/health interp packages/wj-uuid apps/wj-hello

# prove the gate itself catches a planted failure, a planted hang and planted drift
wj run --interpret ... scripts/health_gate.wj --self-test "$WJ" /tmp/health-selftest
```

Environment knobs: `HEALTH_TIMEOUT` (seconds per package and mode, default 600), `HEALTH_JOBS` (packages at once,
default 2), `SLOT_CMD` (a command prefix that wraps each compiled `wj test`, such as a shared build-slot wrapper; empty by
default), `HEALTH_LEDGER` (default `scripts/health-known-failures.txt`).

### Build order

Every package and app is a directory with its own `wj.toml`. The gate reads the `path = "..."` dependencies of each manifest
and runs the directories in waves: a directory starts only after every directory it points at has finished, so an app is
never built before (or while) the package whose generated `build/` crate it depends on. The directories of one wave run
together (`HEALTH_JOBS`). In compiled mode a directory whose dependency did not pass is reported once as `blocked`
(`dependency failed: <dir>`), not as a second failure or as interpreted-versus-compiled drift; the failed dependency is the one violation.
The self-test builds a one-package, one-app fixture and fails if the app is ever scheduled with or before its package.

### What the numbers mean

`<outdir>/results.json` has one entry per directory and mode: `status` (`pass`, `fail`, `timeout`, `skip`), the
`passed` and `failed` test counts, `seconds` and a `duration_class` (`fast` under 10 s, `medium` under 60 s, `slow`
under 300 s, `very-slow` beyond), plus a `comparison` block. A package shows **drift** when its interpreted and
compiled runs disagree on outcome or on pass/fail counts: that is the interpreter and the compiler giving different
answers for the same program, which we treat as a bug in one of them. The `summary` block gives interpreted and
compiled package totals, total passing tests per mode and the drift count.

### The known-failures ledger

`scripts/health-known-failures.txt` lists accepted failures as `dir | mode | reason | owner`, where mode is `interp`,
`compiled` or `drift`. It only shrinks:

- a failure or drift that is not in the ledger fails the gate (a new regression);
- an entry whose problem has been fixed also fails the gate until the line is deleted, so fixes are locked in.

`--self-test` is the mutation check for the gate: it feeds planted failing, hanging and drifting results through the
same decision code and runs real planted packages through the runner, and fails if the gate ever lets one through.

### CI

Job `health-interpreted` in `.github/workflows/ci.yml` builds the pinned `wj`, runs the self-test and sweeps every
package and app interpreted. Job `health-compiled` runs weekly and on demand (`workflow_dispatch`); it adds the
compiled sweep and drift comparison and does not block merges. Both upload `results.json`.

`scripts/health_sweep.wj` is the lighter TSV sweeper that feeds `scripts/health_table.wj` (the table in
`docs/STDLIB_GRADUATION.md`).
